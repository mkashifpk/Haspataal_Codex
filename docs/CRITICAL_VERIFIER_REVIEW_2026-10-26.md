## Purpose and design

The independent laboratory verifier opens this screen immediately after a released critical value or priority disease, tells the responsible clinician, records each actual communication, and tracks the separate physician acknowledgement and health-authority obligation. The queue/detail layout keeps patient identity and the urgent action visible together; keyboard labels, F1, shared bounded zoom and bilingual help support interruptions and Urdu terminals. Existing project components/styles are reused; no separate clinical policy or timer is invented. Design owner/H09, alert policyH10, Urdu/clinical wordingH08 and named editor acceptance remain human-owned.

MCP explicitly lists `critical_results_bench` as the same component. `src/screens/CriticalResultsBench.tsx` now accepts only the bench/verifier screen IDs; the exact selected ID controls runtime service access, fresh write preflight, draft write scope and contextual help. `src/App.tsx` admits the verifier route only through scoped handbook, current permissions and establishment views. Native alarm maps the actual authenticated window workspace to its own service screen and rechecks actor/window/record/service before sound. The existing technician route keeps its default scope. Neither role can acknowledge clinically here.
