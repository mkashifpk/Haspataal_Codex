## Delivered scope

During rounds, the doctor, clinical specialist or surgeon verifies the selected patient and treating doctor, reads observations and medicines, records missing admission details once, and begins clinical discharge when the prerequisites exist. Uses established shell/patient/write/recovery patterns; design ownership H09 and native Urdu remain pending. No facility-category or role-name permission branch.

`src/screens/DoctorInpatients.tsx` and generated contracts provide all-live admission list, local name/MRN/doctor search, server status/history filter, known-reference read, optional photo, patient flags and author-stamped reason/diagnosis/plan. The server offers no doctor list filter here: the UI explicitly says all admissions available to the account, never silently assumes they belong to the signed-in doctor. Patient identity is checked through actual profile reads, with allergies as recorded/Not recorded, age/DOB, MLC/temp/merge/death flags and dues. Changing context clears old detail/profile/flow/MAR/document data and invalidates file callbacks.

Flowsheet and MAR are read-only: observed/recorded times, scheduled due time, corrections, nursing author stamps and medication/check/variance data. No medicine order or administration is implemented here. Empty states are explicit; populated clinical grids still need human review. Optional patient photo is separate from the outside-document viewer. Outside reports show actual facility/date separately from hospital documents; images preview and PDFs save through the protected native downloader.

Missing Code Red details are recorded once. Clinical discharge sends only its note, with current actor/view/patient/exact-record preflight; it starts the clinical stage and never frees the bed. Both writes are state guarded: no automatic retry or replay after a lost response. Read/reconcile retains input; an already completed action remains unavailable. Refusals are handled by code and reread admission/clearance progress; details.fields uses shared field associations. Final details/stages show their recorded authors/times. `inpatient-policy.ts` has meaningful state/view/permission/snapshot/event targeting tests. Unrelated admission events update the list without interrupting the selected review; matching events/reconnect refresh and stop stale reviews.

App routing follows GET establishment views for inpatient, plus current permissions/handbook. Full and open_work permit existing work; records/hidden/setup do not expose clinical actions. Runtime service transitions/all roles remain human acceptance work. Existing Doctor estimate screen now accepts the chart's actual admission, reads filtered estimates and returns to that same chart. No typed admission ID is sent to prepare/explain. English/Urdu F1/control help, Doctor/specialist/surgeon FAQs, workspace guidance, real media and shared 100–250% zoom accompany the screen.

Summary, Doctor-consent and death editors are later screens. Their unavailable handovers are stated honestly; no mock route/editor or prerequisite bypass. Missing-summary refusal keeps the note and hands over to the authorised clinician; general consent goes to Admissions until the Doctor consent screen exists. No full rule claim for these later editors/death flow.
